# 🔐 Nexus Mind Vault — Step-by-Step Demo Walkthrough

> A complete journey from the ordinary cover journal to the hidden cognitive enclave.

## 🚀 Phase 1 — Enter the App

### Step 1 — Launch Nexus Mind Vault

Open the live showcase:

- **Showcase:** https://nexusaitech.in/apps/nmv/index.html
- **Production:** https://nexus-mind-vault-n4ekvxi54q-uc.a.run.app/

### Step 2 — Authenticate

Sign in using **Firebase Authentication** — Google Sign-In or email authentication.

### Step 3 — Arrive at the Protected Vault

You land in the **Protected Vault (PV)** — the default cover surface.

At first, it appears empty and completely ordinary.

**Nothing here reveals that another vault exists.**

> 🛡️ **Design principle:** The safest secret is one whose existence is never revealed.

## 🕵️ Phase 2 — Discover the Covert Stealth Gate

### Step 4 — Activate the Hidden Gate

Press and hold the application logo for approximately **10 seconds**.

There is deliberately **no visible progress indicator or unlock prompt**.

### Step 5 — Enter the Secret Code

The **Covert Stealth Gate** silently appears.

Enter your Secret Code to access the true vault.

> 🔐 **The gate is discoverable only to someone who knows where—and how—to look.**

### Step 6 — Open the Semantic Memory Graph

### Step 7 — Select a Real Entry

Choose a genuine sensitive journal entry and run **NPPM Topological Domain Translation**.

### Step 8 — Choose a Cover Domain

Select from **six curated cover domains**, or define a completely custom domain.

### Step 9 — Generate the Cover Narrative

NPPM translates the entry into the selected cover domain while attempting to preserve:

> 🎭 **The goal:** provide a convincing alternative explanation for what the app contains.

## 🔐 Phase 5 — Demonstrate the Duress Defense

This is the centerpiece of the security demonstration.

### Step 12 — Configure the Duress PIN

Open:

**Vault Settings → Duress PIN**

Set your own Duress PIN, or use the demo PIN:

**999888**

### Step 13 — Simulate Coercion

Sign out.

At the PIN screen, enter the **Duress PIN** instead of the Master PIN.

### Step 14 — Observe the Decoy Mode

The application opens into the **Protected Vault / decoy persona**.

Now attempt to activate the Covert Stealth Gate.

### ❌ The true vault remains inaccessible.

There is:

- no alarm
- no countdown
- no obvious failure
- no visible indication that a duress mechanism was triggered

From the perspective of the person demanding access, the PIN appears to have worked.

> 🎭 **Master PIN → True Vault**  
> **Duress PIN → Decoy Vault**

Both paths are designed to look legitimate.

## 📓 Phase 8 — Zero-Knowledge Journal Architecture

### Step 18 — Create a Journal Entry

Open **Journal Entries**.

Create an entry containing supported content such as:

- text
- voice notes
- photographs
- location information
- files

### Step 19 — Inspect the Network Layer

Open browser DevTools and inspect the **Network** tab.

Demonstrate that sensitive journal content is encrypted **client-side** before transmission.

The architecture uses:

- 🔒 **AES-GCM-256**
- 🔑 **PBKDF2-SHA256 with 600,000 iterations**
- 🧠 **Volatile in-memory key handling**

The intended flow is:

**Plaintext → Browser Encryption → Ciphertext → Server**

rather than:

**Plaintext → Server → Encryption**

> 🔐 **The security claim is intended to be inspectable: the server receives ciphertext rather than plaintext journal content.**
